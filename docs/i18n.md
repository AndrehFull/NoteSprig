# Languages and translation

NoteSprig supports **English (`en`)** and **Brazilian Portuguese (`pt-BR`)**. English is the default for a new browser profile or an unsupported stored preference.

## Choose a language

Use the selector on the login screen or open **Settings → Language**. The choice is stored as `notesprig.language` in this browser. Open tabs on the same origin follow changes through the browser storage event. The language catalogs are bundled locally, so switching does not require a translation service or an internet connection.

The document's HTML language, interface labels, accessibility labels, messages, date formatting, and editor search phrases follow the selection. Browser-owned media controls, the native PDF viewer, and external sites use their own language settings.

Changing language does not translate user-authored notes, property names or values, existing view names, file paths, or folder settings. Generated template date names follow the current locale when inserted; existing content is preserved. The editor updates its search phrases without recreating its document or undo history.

## Project documentation

The default [README](../README.md), technical guides, contributor guidance, API messages, and command-line tools use English. The [Brazilian Portuguese README](../README.pt-BR.md) introduces the same application and links to the technical guides. Test vaults intentionally contain multilingual notes.

## Maintain translations

Catalogs live in `src/locales/en.json` and `src/locales/pt-BR.json`. Their keys are English source messages. Use `t('Message')` for interface text and named placeholders for dynamic values:

```ts
t('Close {v0}', { v0: fileName })
```

Keep placeholder names identical in both catalogs. Add complete messages where practical so translators can control word order. Do not translate document-format identifiers, URLs, CSS classes, persisted schema values, or user content.

`translateMessage` adapts known application errors and notices, including messages created before a language change. Use it only for application messages. Unknown technical errors retain their original text. CodeMirror uses the locale catalog through its phrase configuration.

Run the checks before submitting:

```sh
npm run check:i18n
npm run check:docs
npm run test:ui
```

The catalog check verifies key parity, nonempty translations, placeholder parity, and literal translation keys referenced by the source. Browser tests cover default language, authentication errors, persistence, cross-tab updates, offline drafts, editor undo, and search phrases in both languages.
